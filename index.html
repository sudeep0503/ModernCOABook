CHAPTER 01

Bits, logic and circuits: the physical alphabet

Everything a computer stores or computes is encoded as physical electrical states interpreted as 0s and 1s. This chapter builds the bridge from voltage ranges on a wire to a fast binary adder.

1.1 A bit is a decision, not a physical pebble

A bit (binary digit) represents one of two states: 0 or 1. Inside silicon, a bit is represented by a voltage range, capacitor charge, or transistor switch state. Digital circuits do not require infinitely accurate voltages—they define a safe LOW band (0) and a safe HIGH band (1) separated by a forbidden noise margin.

Light-switch analogy: A dimmer dial has countless positions, making small bumps hard to distinguish. A binary light switch snaps cleanly to OFF or ON. Digital silicon trades infinite nuance for rock-solid noise immunity.

Eight bits form one byte (256 distinct patterns). In general, n bits represent 2^n unique bit patterns, giving an unsigned integer range of 0 to 2^n − 1.

1.2 Binary, hexadecimal and two's complement

Binary is base 2; hexadecimal (hex) is base 16. Because 16 = 2⁴, every single hex digit maps cleanly to exactly 4 bits: 1101 1010₂ = DA₁₆. To convert binary to decimal, sum the powers of 2 where bits equal 1: 101101₂ = 32 + 8 + 4 + 1 = 45.

Two's complement is the universal representation for signed integers. An n-bit signed number spans −2^(n−1) to +2^(n−1) − 1, where the most significant bit (MSB) has negative weight −2^(n−1). To negate any value x, invert every bit (one's complement) and add 1. In 8 bits: +5 = 00000101 → invert 11111010 → add 1 → 11111011 = −5. Notice that zero has only one encoding (00000000).

GATE checkpoint — Carry vs. Overflow: The exact same hardware adder adds signed and unsigned numbers, but the error condition differs:
• Unsigned overflow occurs when Carry-out (C) = 1.
• Signed (two's complement) overflow (V) occurs when two numbers of the same sign produce a sum of the opposite sign—equivalently, V = C_in(MSB) XOR C_out(MSB).

Boolean logic gates turn input bits into output bits. NAND and NOR are functionally complete (universal): any Boolean circuit in an entire CPU can be constructed exclusively from NAND gates, or exclusively from NOR gates.

1.4 Combinational versus sequential circuits

A combinational circuit has no memory: its output depends strictly on its present inputs (adders, multiplexers, decoders, comparators). A sequential circuit includes state-holding elements—latches (level-sensitive) or flip-flops (clock-edge-triggered)—whose outputs feed back into the logic. Grouping flip-flops together creates a register.

1.5 Adders: Ripple-Carry vs. Carry-Lookahead (CLA)

A half adder adds two 1-bit inputs: Sum = A ⊕ B and Carry = A · B. A full adder also accepts a carry-in (C_in) from the previous bit column:

Sum = A ⊕ B ⊕ C_in   |   C_out = (A · B) + C_in · (A ⊕ B)

Chaining n full adders creates an n-bit ripple-carry adder. It is compact, but the carry may have to ripple sequentially across all n bits—giving O(n) delay. A Carry-Lookahead Adder (CLA) speeds this up by precomputing two signals at every bit position i in parallel:

Generate: G_i = A_i · B_i  (produces a carry unconditionally)
Propagate: P_i = A_i ⊕ B_i  (passes an incoming carry onward)
C_(i+1) = G_i + P_i · C_i   ⇒   C_2 = G_1 + P_1·G_0 + P_1·P_0·C_0

Because carries are computed in parallel trees instead of waiting bit-by-bit, CLA and parallel-prefix adders reduce delay toward O(log n) at the expense of extra gates and wiring.

1.6 Clocking and physical timing constraints

A clock is a periodic square wave with frequency f = 1/T. At 3 GHz, one clock cycle is T ≈ 0.333 ns. For a sequential circuit to capture data reliably, every path between flip-flops must obey four physical timing rules:

  • Propagation delay (t_pd): The time it takes a signal change at a gate's input to travel through logic and settle at its output.
  • Setup time (t_su): How early data must arrive and stay steady before the rising clock edge.
  • Hold time (t_h): How long data must remain steady after the rising clock edge.
  • Clock skew & jitter: Skew is the fixed spatial difference in clock arrival time between two flip-flops on the chip; jitter is random cycle-to-cycle variation in clock edge timing.
Minimum clock period:   T_min ≥ t_clk-to-Q + t_logic(max) + t_setup + t_skew

CHAPTER 02

System architecture: buses, I/O and DMA

A computer is not a single monolithic brain—it is a set of specialised blocks exchanging instructions and data over well-defined communication contracts.

2.1 Von Neumann versus Harvard architecture

In a stored-program computer, both executable instructions and program data live in memory as bit patterns. The classic von Neumann architecture shares one memory bus for both instructions and data, creating the von Neumann bottleneck (the CPU cannot fetch an instruction and load data from the same bus simultaneously). The Harvard architecture provides separate instruction and data memories with independent buses.

Modern CPUs get the best of both worlds via a modified Harvard design: software sees one unified address space (like von Neumann), while the CPU core internally splits its fastest L1 cache into separate L1 Instruction (L1i) and L1 Data (L1d) caches so instruction fetches and data loads happen in parallel.

2.2 Address, data and control roles

Whether a link is an older parallel bus or a modern serial packet interconnect like PCI Express (Chapter 10), every transfer carries three logical roles:

  • Address: Identifies where (which memory byte or I/O register) the transfer targets.
  • Data: Carries the actual payload bits being read or written.
  • Control: Coordinates what and when—read/write direction, bus request/grant (arbitration), interrupts, and byte-enable signals.

Never confuse address width with data width. In a byte-addressable system, an n-bit address bus can uniquely name 2^n bytes (e.g., 32 bits = 2³² B = 4 GiB). Independently, a 64-bit data bus transfers 8 bytes per beat.

Theoretical peak bus bandwidth = (Data width in bits ÷ 8) × Transfers per second

Real throughput is always lower than this theoretical peak due to arbitration delays, command overhead, and bus turnaround cycles.

2.3 Memory-mapped I/O versus Isolated (Port-mapped) I/O

CPUs communicate with keyboards, disks, and network cards by reading and writing special device registers (status, control, data).

  • Memory-Mapped I/O (MMIO): Device registers are assigned addresses inside the normal physical memory address space. The CPU uses ordinary LOAD and STORE instructions to talk to hardware. (Used by Arm, RISC-V, and almost all modern PCIe devices on x86.)
  • Isolated (Port-Mapped) I/O: Devices live in a separate I/O address space accessed only by dedicated CPU instructions (such as legacy x86 IN and OUT).
Service counter analogy: Think of a device's status register as the “Now Serving” display at a bakery counter. The CPU glances at the board (“Ready / Busy / Error”), drops an order into the control register, and picks up finished goods from the data register.

2.4 I/O Transfer Modes: Polling, Interrupts and DMA

Moving bytes between a peripheral and RAM can be handled in three progressively smarter ways:

  1. Programmed I/O (Polling): The CPU sits in a loop repeatedly reading the device's status register until it is ready, then copies data word-by-word. Simple, but burns CPU cycles waiting.
  2. Interrupt-Driven I/O: The CPU starts a request and goes back to useful work. When the device is ready, it asserts an electrical interrupt signal; the CPU pauses its current program, runs an Interrupt Service Routine (ISR) to move data, and resumes. Great for slow/sporadic devices (keyboard, mouse), but high-speed disks/NICs would flood the CPU with millions of interrupts per second.
  3. Direct Memory Access (DMA): The CPU configures a dedicated DMA controller with three parameters—source/destination address, byte count, and direction—and walks away. The DMA controller moves the entire block directly between the device and RAM, raising one interrupt only when the whole block finishes.

Worked GATE Example — DMA Cycle Stealing: A hard disk produces data at 2 MB/s (decimal: 2 × 10⁶ B/s) and transfers 32-bit (4-byte) words to RAM via DMA cycle stealing. Each DMA word transfer occupies the memory bus for 100 ns. What percentage of time is the CPU blocked from using the bus?
Step 1: Word transfers per second = 2,000,000 B/s ÷ 4 B/word = 500,000 transfers/s.
Step 2: Total bus time stolen per second = 500,000 × 100 × 10⁻⁹ s = 0.05 s.
Answer: The CPU is blocked for 5% of the time.

Note that DMA is not completely “free”: because devices read/write RAM directly, the system must ensure cache coherency (so the CPU does not read stale cached copies of overwritten RAM) and use an IOMMU (I/O Memory Management Unit, detailed in Chapter 10) to isolate which memory addresses a device is allowed to touch.

Instruction sets, registers and addressing modes

The Instruction Set Architecture (ISA) is the legal contract between compiler writers and chip designers. It defines what operations exist, how operands are located, and which byte order memory uses.

3.1 Instruction encoding and formats

Every machine instruction is a binary word divided into bit fields: an opcode (what operation to run), register identifiers (source/destination), and optional immediate constants or function sub-codes. 3.2 Architectural registers

Registers are tiny, sub-nanosecond storage slots built right next to the execution units and named directly inside instructions:

  • General-Purpose Registers (GPRs): Hold integers, loop counters, and pointers (e.g., 16 GPRs in x86-64, 31 in AArch64 and RISC-V).
  • Program Counter (PC / RIP): Holds the memory address of the current (or next) instruction to fetch.
  • Stack Pointer (SP): Points to the top of the call stack for function arguments and local variables.
  • Status / Flags Register: Stores condition bits—Zero (Z), Negative (N), Carry (C), Overflow (V)—used by conditional branches.
  • Vector / Floating-Point Registers: Wide registers (128 to 512 bits) holding floating-point values or packed SIMD lanes.
  • Control / System Registers: Privileged registers configuring page-table base addresses, interrupt vectors, and security modes.
Chef's counter analogy: Registers are the prep bowls right beside your cutting board. You can grab from them instantly, but counter space is scarce—when a recipe needs more ingredients, you fetch them from the shelf (cache) or pantry (RAM).

3.3 CISC, RISC and modern reality

CISC (Complex Instruction Set Computer, e.g., x86-64) uses variable-length instructions (1–15 bytes) and allows arithmetic instructions to directly read or modify memory operands. RISC (Reduced Instruction Set Computer, e.g., Arm AArch64, RISC-V) favours fixed-width instructions and a load/store architecture where ALU instructions touch only registers, while explicit LOAD/STORE instructions touch memory.

Avoid the outdated myth that “CISC is slow, RISC is fast.” Modern x86 CPUs translate complex variable-length instructions inside the front-end decoder into simpler RISC-like internal micro-operations (µops), while modern Arm and RISC-V cores pack huge out-of-order engines and SIMD extensions. Today, microarchitecture and power budget matter far more than the CISC/RISC label.

CHAPTER 04

ALU, datapath and IEEE-754 floating point

The Arithmetic Logic Unit (ALU) is the engine that transforms bits; the datapath is the highway system—wires, multiplexers, and registers—that feeds operands into the ALU and routes results back.

4.1 ALU operations, subtraction and shifters

An integer ALU executes addition, subtraction, bitwise logic (AND, OR, XOR, NOT), comparisons, and shifts. Subtraction reuses the exact same adder hardware via two's complement:

A − B = A + (NOT B) + 1   (invert B with XOR gates and set C_in = 1)

Shifters move bits left or right in a single cycle (via a barrel shifter). Logical shifts insert 0s; arithmetic right shift duplicates the sign bit so negative numbers stay negative. Caution: for odd negative numbers, arithmetic right shift rounds toward −∞ (e.g., −5 >> 1 = −3), whereas C/Java integer division truncates toward zero (−5 / 2 = −2).

For multiplication of signed two's complement integers, hardware algorithms such as Booth's algorithm scan pairs of multiplier bits to replace long runs of 1s with a single subtraction and addition, reducing the number of partial products.

4.2 Complete single-cycle teaching datapath

A real teaching datapath requires multiplexers (MUXes) to select between competing sources: Does the PC get PC + 4 or a branch target? Does the ALU's second input come from a register or an immediate constant? Does the Register File receive the ALU's output or a word loaded from Data Cache?

Railroad switch analogy: A multiplexer (MUX) is a train track switch. Control signals throw the lever to decide whether the ALU receives a second register or a constant from the instruction—without changing the track itself.

4.3 IEEE-754 Floating-Point representation

Integers cannot express astronomical distances (6.02 × 10²³) or sub-atomic lengths (1.6 × 10⁻¹⁹) in 32 bits. The IEEE-754 standard represents real numbers in binary scientific notation using three fields: Sign (S), Biased Exponent (E), and Fraction / Mantissa (F).

Special exponent patterns are reserved: E = 0 represents ±0 (if F = 0) or subnormal numbers (0.F × 2⁻¹²⁶, dropping the implicit leading 1 to allow gradual underflow near zero). E = 255 (all 1s) represents ±∞ (if F = 0) or NaN (Not a Number, if F ≠ 0). Notice that simple decimals like 0.1₁₀ repeat infinitely in binary (0.0001100110011...₂) and cannot be stored exactly.

4.4 SIMD and vector execution units

SIMD (Single Instruction, Multiple Data) packs multiple numbers into one wide vector register so a single instruction executes 4, 8, or 16 arithmetic operations simultaneously (e.g., x86 AVX2/AVX-512, Arm NEON/SVE, RISC-V Vector). SIMD shines on image filters, audio DSP, and linear algebra where adjacent array elements undergo identical math.

CHAPTER 05

Control unit and microprogramming

If the datapath is an orchestra of ALUs, registers, and multiplexers, the control unit is the conductor—turning each fetched opcode into the exact sequence of electrical control signals needed to execute it.

5.1 The classic instruction cycle

  1. Fetch: Read instruction bytes from Mem[PC] into the Instruction Register (IR) and advance PC.
  2. Decode: Inspect the opcode and register fields to determine what operation is requested.
  3. Operand Fetch: Read source registers or compute effective addresses.
  4. Execute: Run the ALU, floating-point unit, or branch comparison.
  5. Memory Access: Read or write Data Cache if the instruction is a load or store.
  6. Write-Back: Commit the result into the destination register and update status flags.

5.4 Single-cycle, Multi-cycle and CPI

In a single-cycle CPU, every instruction completes in 1 clock cycle—so the clock must be slow enough to fit the slowest instruction (usually a memory load). A multi-cycle CPU splits execution into shorter steps via a Finite-State Machine (FSM): fast instructions (branches, adds) take fewer cycles while loads take more, allowing a much faster clock.

This leads to the fundamental performance law (explored in full in Chapter 14): CPU Time = Instruction Count × CPI × Cycle Time. Reducing CPI, instruction count, or cycle time in isolation only wins if it does not worsen the other two.

Chapter 5 Summary: Hardwired FSMs excel at speed; microprogrammed stores excel at flexibility; vertical encoding shrinks microinstruction width using ⌈log₂(n+1)⌉ bits per mutually exclusive group at the cost of decoder delay.
CHAPTER 06

Pipelines, hazards and out-of-order CPUs

Making a single instruction finish faster hits hard physics limits. Modern CPUs achieve speed instead by overlapping instructions like an assembly line, forwarding intermediate results, predicting branches, and executing independent work out of order.

6.1 Classic 5-stage pipeline and unequal stage delays

A textbook 5-stage RISC pipeline splits every instruction into IF (Instruction Fetch), ID (Decode / Register Read), EX (Execute / ALU), MEM (Data Cache Access), and WB (Write-Back). Between every pair of stages sits a pipeline register (latch) that holds intermediate values on each clock edge.

In an ideal k-stage pipeline with n independent instructions, total cycles equal k + n − 1 (versus k × n without pipelining). Real stages rarely have identical delays, so the pipeline clock must be slow enough for the slowest stage plus inter-stage latch overhead:

T_non-pipe = Σ t_i   |   T_pipe = max(t_1, t_2, ..., t_k) + t_latch   |   Steady-state Speedup = T_non-pipe / T_pipe
Laundry assembly-line analogy: Washing (30 min), drying (45 min), and folding (20 min) one load takes 95 minutes. Pipelining does not wash one shirt faster—it starts the next load while the first dries. However, the conveyor belt can only advance every 45 minutes (the slowest stage, drying) plus a few minutes to move baskets (latch delay).

6.2 Pipeline hazards, stalls and operand forwarding

Hazards occur when the next instruction cannot enter its next stage on the next clock cycle:

  • Structural hazard: Two instructions need the same hardware unit simultaneously (e.g., unified memory accessed by both IF and MEM—solved by separate L1i/L1d caches).
  • Data hazard: An instruction needs a value not yet written back. RAW (Read After Write) is a true data dependency; WAR (Write After Read) and WAW (Write After Write) are false name dependencies.
  • Control hazard: A branch or jump changes the PC, so the CPU does not yet know which instruction to fetch next.

Operand forwarding (bypassing) routes an ALU or memory result directly from an internal pipeline latch back into the EX stage inputs—eliminating stalls for back-to-back ALU instructions and cutting a load-use hazard from 2 stall cycles down to 1 stall cycle.

6.3 Branch prediction and Effective CPI (GATE Formula)

Waiting for every conditional branch to resolve stalls the front end. Modern CPUs use dynamic branch predictors (combining Branch History Tables, Branch Target Buffers, and Return Address Stacks) to predict direction and target address speculatively. Correct predictions cost 0 penalty; a misprediction flushes speculative instructions and incurs a branch penalty:

Effective CPI = CPI_ideal + (Branch_freq × Misprediction_rate × Branch_penalty) + Data_stall_CPI
Worked GATE Example — Effective Pipeline CPI: A 5-stage pipeline has ideal CPI = 1. Branches make up 20% of instructions, the branch predictor is 85% accurate (so 15% mispredict), and each misprediction flushes 3 cycles. What is the effective CPI?
Solution: CPI = 1 + (0.20 × 0.15 × 3) = 1 + 0.09 = 1.09.

6.4 Superscalar, Out-of-Order (OoO) execution and Register Renaming

A superscalar core fetches, decodes, and executes multiple instructions per cycle (e.g., 4-wide to 8-wide). To keep all those execution ports busy despite cache misses and dependencies, high-performance CPUs use Out-of-Order (OoO) execution:

  1. Register Renaming: Maps the small set of ISA architectural registers onto a much larger internal Physical Register File (PRF), eliminating false WAR and WAW hazards.
  2. Dispatch to both Issue Queue & Reorder Buffer (ROB): Renamed µops enter the Issue Queue (waiting for their operands) AND allocate a slot in program order inside the ROB.
  3. Out-of-Order Execution: As soon as any µop's operands are ready, the scheduler dispatches it to an ALU, FPU, or Load/Store unit—even if older instructions are still stalled on a DRAM miss.
  4. In-Order Retirement (Commit): Execution units write results to the PRF and mark the instruction complete in the ROB. The ROB retires instructions strictly in original program order so exceptions and mispredictions recover cleanly.

6.5 SMT (Hyper-Threading) and Hybrid P-cores / E-cores

Simultaneous Multithreading (SMT) lets one physical core track two independent thread contexts (duplicating PC and architectural registers) while sharing the core's caches and execution ports. When Thread A stalls waiting on DRAM, Thread B feeds the idle ALUs. Two logical CPUs are not equal to two full physical cores—typical real-world SMT speedup is 15–35%, not 100%.

Modern client CPUs also adopt heterogeneous (hybrid) cores: wide, power-hungry P-cores (Performance) for latency-sensitive foreground work paired with compact E-cores (Efficiency) for background tasks and dense multi-threaded throughput per watt. Hardware feedback hints help the OS scheduler match threads to the right core class. For how multiple dies are physically packaged inside a processor, see Chiplets in Section 13.2.

Chapter 6 Summary: Pipeline clock period is set by max(stage) + latch; operand forwarding resolves ALU-to-ALU RAW hazards with 0 stalls and Load-Use hazards with 1 stall; OoO execution decouples execution from in-order ROB retirement; SMT shares one core while hybrid cores balance single-thread speed and efficiency.
CHAPTER 07

Cache, virtual memory and coherence

CPUs execute billions of instructions per second, yet fetching a single byte from DRAM takes hundreds of CPU cycles. Caches bridge that speed gap using locality, while virtual memory isolates and simplifies every running program.

7.1 Memory hierarchy, locality and AMAT

Programs rarely jump across RAM at random. They exhibit temporal locality (recently accessed items are likely to be reused soon, e.g., loop counters) and spatial locality (items near a recently accessed address will likely be accessed next, e.g., iterating over an array). Caches transfer fixed blocks called cache lines (commonly 64 bytes) to harvest spatial locality automatically.

Cache misses fall into the classic 3 Cs (plus a 4th in multicores): Compulsory (cold first access), Capacity (working set exceeds cache size), Conflict (multiple blocks compete for the same set), and Coherence (invalidated by another core).

1-Level AMAT = Hit_time + Miss_rate × Miss_penalty
2-Level AMAT = T_L1 + MR_L1 × (T_L2 + MR_L2(local) × T_DRAM)

Always distinguish local miss rate (misses at L2 divided by accesses reaching L2) from global miss rate (misses at L2 divided by all CPU memory references, equal to MR_L1 × MR_L2(local)).

7.2 Address decomposition and Set-Associative lookup hardware

For a cache of total data capacity C bytes, line size B bytes, and associativity A ways (A = 1 for direct-mapped; A = C/B for fully associative):

Lines = C / B   |   Sets S = Lines / A   |   Offset = log₂(B)   |   Index = log₂(S)   |   Tag = Addr_bits − Index − Offset
Worked GATE Example — Total Cache SRAM Size (Data + Metadata Overhead): A 32-bit physical address feeds a 32 KiB, 4-way set-associative, write-back cache with 64-byte lines. Each line stores 1 Valid bit, 1 Dirty bit, and 2 LRU bits. Find the Tag directory size and total SRAM required.
Step 1: Total lines = 32,768 / 64 = 512. Sets = 512 / 4 = 128 = 2⁷ ⇒ Index = 7 bits, Offset = log₂(64) = 6 bits.
Step 2: Tag = 32 − 7 − 6 = 19 bits.
Step 3: Metadata per line = 19 (tag) + 1 (V) + 1 (D) + 2 (LRU) = 23 bits.
Step 4: Tag directory = 512 × 23 = 11,776 bits = 1,472 bytes ≈ 1.44 KiB. Total SRAM = 32 KiB + 1.44 KiB = 33.44 KiB.

7.3 Replacement and write policies

When a set is full, a replacement policy picks the victim line: LRU (Least Recently Used), Pseudo-LRU (tree-based approximation used in real hardware for 8-way+ caches), FIFO, or Random. For writes: Write-through updates cache and lower memory immediately; Write-back sets a Dirty bit and writes back to RAM only when evicted (cutting memory traffic dramatically). On a write miss, Write-allocate fetches the line into cache first (usually paired with write-back), while No-write-allocate writes straight to lower memory (often paired with write-through).

7.4 Virtual memory, Multi-level Page Tables and TLB

Programs execute using virtual addresses, giving every process a clean, private address space larger than physical RAM if needed. The Memory Management Unit (MMU) translates each Virtual Page Number (VPN) into a Physical Frame Number (PFN) using OS-managed page tables while copying the page offset (12 bits for 4 KiB pages) unchanged.

Because a flat single-level page table for a 48-bit virtual address space would waste gigabytes per process, modern CPUs use multi-level page tables (e.g., 4-level paging in x86-64/AArch64) and require 64-bit addresses to be canonical (upper unused bits sign-extended). To avoid walking RAM page tables on every memory access, the CPU caches recent translations in a fast associative SRAM called the Translation Lookaside Buffer (TLB).

Worked GATE Example — TLB Effective Memory Access Time (EMAT): A system has a TLB access time of 1 ns, TLB hit rate of 90%, single-level page table in RAM, and RAM access time of 100 ns. Compute EMAT.
Hit path (90%): TLB (1 ns) + Data RAM (100 ns) = 101 ns.
Miss path (10%): TLB (1 ns) + Page Table RAM (100 ns) + Data RAM (100 ns) = 201 ns.
EMAT: 0.90 × 101 + 0.10 × 201 = 90.9 + 20.1 = 111.0 ns.

7.5 Cache coherence versus Memory consistency

In a multicore CPU, two cores can cache the same memory line. Cache coherence ensures all cores agree on the value of any single memory location. The classic MESI protocol tags every cache line as Modified (dirty, exclusive), Exclusive (clean, only copy), Shared (clean, may exist in other cores), or Invalid—coordinated via bus snooping or a directory. Memory consistency is a broader contract: it defines the legal ordering of reads and writes across different memory addresses visible to multithreaded software (e.g., x86's stricter TSO model vs. Arm/RISC-V's relaxed memory model requiring memory barriers).

Shared whiteboard analogy: Coherence guarantees that if Chef A edits the salt amount on line 3 of a recipe, Chef B's sticky-note copy of line 3 is crossed out immediately. Consistency defines whether Chef B is guaranteed to see the salt edit before seeing Chef A's note on line 9 saying “soup is ready.”
Chapter 7 Summary: Caches harness temporal and spatial locality; always include Valid/Dirty/LRU bits when computing cache SRAM size; TLBs accelerate virtual-to-physical translation; and MESI coherence (single address) is distinct from memory consistency (ordering across addresses).
CHAPTER 08

Main memory: DRAM, DDR and memory channels

RAM is the computer's active volatile workspace. Decoding labels like “DDR5-6400 CL32” means understanding capacitors, rows, banks, ranks, channels, and double-data-rate signalling.

8.1 SRAM versus DRAM cells

SRAM (Static RAM, used in CPU caches) stores each bit in a pair of cross-coupled inverters (typically 6 transistors per bit). It is blazingly fast and never needs refresh while powered, but consumes large silicon area. DRAM (Dynamic RAM, used in system memory and GPU VRAM) uses a single access transistor and a microscopic capacitor (1T1C cell). Because capacitor charge leaks away in milliseconds, DRAM must be periodically refreshed—and reading a cell destroys its charge, requiring an immediate internal write-back.

8.2 Banks, rows, columns and DRAM timing

Warehouse analogy: Think of your memory system as a fulfilment centre. Channels are independent loading docks, banks are parallel warehouse aisles workers can visit simultaneously, a row is one long shelf pulled out onto a sorting table (row buffer), and columns are individual boxes picked off that open shelf. Picking a second box from the already-open shelf (a row-buffer hit) is far faster than putting the shelf back and pulling out a new one (a row conflict).

Memory controllers orchestrate DRAM with four core commands: ACT (activate/open a row into the row buffer), READ/WRITE (burst data from/to columns), PRE (precharge/close the row), and REF (refresh rows). Memory timings are measured in clock cycles: tRCD (ACT to READ), CL/tCAS (READ to first data), tRP (PRE to next ACT), tRAS (minimum row open time), and tRFC (refresh cycle). Convert CAS latency into real nanoseconds via:

True CAS Latency (ns) = (CL × 2000) / Data_Rate_in_MT/s   (e.g., DDR5-6400 CL32 ⇒ 32×2000 / 6400 = 10.0 ns)

8.3 DDR generations, MT/s vs. MHz, Channels and Ranks

DDR (Double Data Rate) transfers data on both rising and falling clock edges. Always measure DDR speed in MT/s (million transfers per second), not MHz: DDR5-6400 runs at 6,400 MT/s using a 3,200 MHz I/O clock.

CPUs prioritise capacity and low latency using DDR. Discrete GPUs and AI accelerators prioritise massive aggregate bandwidth: GDDR (e.g., GDDR6/GDDR7) surrounds a GPU die with very high-speed signalling, while HBM (High Bandwidth Memory) stacks DRAM dies vertically atop a silicon interposer next to the compute die, delivering 1,024-bit+ interfaces per stack at multi-TB/s bandwidth and low energy per bit. For memory error protection (SECDED ECC), see Chapter 16.

Chapter 8 Summary: SRAM is fast and static; DRAM is dense but needs refresh. Use MT/s (not MHz) for DDR speed, compute true CAS latency in nanoseconds, and distinguish channels, subchannels, ranks, banks, GDDR, and HBM.
CHAPTER 09

Persistent storage: HDD, NAND SSD and NVMe

RAM loses everything when power drops. Persistent storage preserves your OS and files using either spinning magnetic platters (HDD) or solid-state flash memory cells (SSD).

9.1 Hard Disk Drive (HDD) mechanics

An HDD stores bits as magnetic orientations on spinning platters organized into concentric tracks and sectors. Total access time is the sum of seek time (moving the mechanical arm to the target track), rotational latency (waiting for the sector to spin under the head), and transfer time.

Full rotation = 60 / RPM seconds   |   Average rotational latency = ½ × (60 / RPM)

At 7,200 RPM, one full spin takes 60 / 7200 = 8.33 ms, so average rotational latency is 4.17 ms—millions of CPU cycles spent just waiting on spinning metal.

9.2 NAND flash, out-of-place writes and write amplification

SSDs store charge inside floating-gate or charge-trap transistors (microscopic insulating pockets that trap electrons to shift a transistor's threshold voltage). Storing more bits per cell—SLC (1 bit), MLC (2 bits), TLC (3 bits), QLC (4 bits)—raises capacity and cuts cost, but tightens voltage sensing margins, lowering write endurance and sustained speed.

Crucially, NAND flash is read/written in pages (e.g., 4–16 KiB) but can only be erased in much larger blocks (hundreds of pages). You cannot overwrite a single page in place.

Sticky-note notebook analogy: Imagine a notebook where you can write on any blank line (a page), but your eraser is so huge it only wipes an entire 200-line chapter (a block) at once. To edit one sentence, you cross out the old line and write the updated sentence on a blank page elsewhere. Later, a cleaner (garbage collection) copies all still-valid lines to a fresh chapter and wipes the old chapter clean. That extra internal copying is called write amplification.

9.3 SSD controller and Flash Translation Layer (FTL)

Because the OS expects clean, overwritable Logical Block Addresses (LBAs), the SSD's embedded processor runs firmware called the Flash Translation Layer (FTL). The FTL maps logical LBAs to physical NAND pages, performs wear levelling (spreading writes evenly so no block wears out early), runs garbage collection, manages bad blocks, and applies strong ECC.

9.4 SATA, NVMe and M.2 — Three separate layers

Never mix these three labels:

  • M.2 is purely a physical card shape and connector (form factor)—not a speed or protocol.
  • PCIe / SATA is the electrical transport interconnect.
  • NVMe / AHCI is the storage command protocol. Older AHCI/SATA allows only 1 queue of 32 commands; NVMe (Non-Volatile Memory Express; specification set 2.4 released August 2026) supports up to 64,000 queues with 64,000 commands each, matching modern multi-core CPUs and multi-die flash parallelism, and also runs over fabrics like RDMA (Remote Direct Memory Access) and TCP.

Also beware headline SSD benchmarks: sustained write speed often drops sharply once a drive's temporary high-speed pseudo-SLC write cache fills up or when the controller thermally throttles. Random 4 KiB read latency at Queue Depth 1 matters far more for everyday OS responsiveness than peak sequential MB/s.

Chapter 9 Summary: HDD latency is mechanical; NAND writes in pages but erases in blocks; the FTL manages wear levelling, garbage collection, and write amplification; and M.2 (form factor), PCIe (interconnect), and NVMe (protocol) are three distinct layers.

CPUs, GPUs, NVMe drives, and network cards communicate over high-speed packetised serial interconnects rather than legacy shared parallel buses.

10.1 PCIe lanes, differential signalling and generations

GPU architecture: why thousands of threads win

A CPU spends its silicon minimising latency for a handful of tricky, branch-heavy threads. A GPU flips the budget—pouring silicon into thousands of lightweight arithmetic lanes and massive memory bandwidth to maximise total throughput.

11.1 CPU versus GPU design philosophy

11.2 Streaming Multiprocessors (SMs), Blocks and Warps

In NVIDIA's CUDA programming model (AMD uses analogous terms: Compute Units and Wavefronts of 32 or 64 threads), a GPU is built from dozens of Streaming Multiprocessors (SMs). Software launches a grid of thread blocks; each block runs on one SM and is sliced into groups of 32 threads called warps.

11.3 SIMT, latency hiding and warp divergence

Under SIMT (Single Instruction, Multiple Threads), all 32 threads in a warp typically step through the same instruction in lockstep on different data elements. When Warp A issues a slow VRAM load, the SM scheduler does not stall—it instantaneously issues an instruction from Warp B, C, or D (because every warp's registers stay live on-chip).

Rowboat & chess-grandmaster analogy: A warp is like a 32-oar rowing crew pulling in rhythm. If half the crew must row forward (if branch) and half backward (else branch), the coxswain must run the forward stroke while half the oars pause in mid-air, then run the backward stroke while the other half pauses—that slowdown is warp divergence. Meanwhile, latency hiding works like a chess grandmaster playing 20 boards simultaneously: while opponent #1 thinks (waiting on VRAM), the grandmaster makes moves on boards #2 through #20.

11.4 GPU memory spaces, coalescing and Tensor Cores

  • Registers: Private per thread, fastest storage on the GPU. Using too many registers per thread reduces occupancy (how many warps fit on an SM simultaneously).
  • Shared Memory: Programmer-managed, ultra-fast on-chip SRAM shared by all threads inside one thread block—essential for tiled matrix multiplication.
  • L1 / L2 Caches & Global Memory (VRAM): High-bandwidth GDDR or HBM shared across the entire device.
  • Local Memory (Naming Trap!): In CUDA, “local” means thread-private scope, NOT on-chip speed—register spills to local memory physically live in slow Global VRAM (cached through L1/L2).

Memory Coalescing: When adjacent threads (0..31) read adjacent addresses in VRAM, the memory controller fuses all 32 reads into a single wide cache-line transaction. Random or strided reads shatter into dozens of wasted transactions.

Modern GPUs also embed dedicated Tensor Cores / Matrix Engines that multiply entire small matrices (e.g., 4×4 or 16×16 tiles) in a single cycle—delivering an order-of-magnitude speedup over scalar FP32 lanes for AI workloads.

When does a GPU beat a CPU? Only when you have (1) thousands of data-parallel elements, (2) coalesced memory access, (3) minimal warp divergence, and (4) enough arithmetic work to pay back the PCIe CPU↔GPU transfer and kernel-launch overhead.
Chapter 11 Summary: GPUs trade single-thread complexity for massive SIMT parallelism and zero-cycle warp switching; avoid warp divergence and uncoalesced VRAM accesses; and remember that CUDA “local” memory resides in device DRAM.
CHAPTER 12

AI accelerators: NPU, TPU, FPGA and numeric precision

Deep learning is overwhelmingly matrix multiplication, attention, and moving huge tensors across memory. Specialised accelerators strip away general-purpose overhead to maximise math per watt.

12.1 The accelerator landscape

  • CPU: General-purpose orchestration, data preprocessing, and branch-heavy control code.
  • GPU: Programmable parallel workhorse; dominates AI training and flexible high-throughput inference.
  • NPU (Neural Processing Unit): Power-efficient matrix/vector block integrated into laptop and phone SoCs for on-device inference (voice, camera, local LLMs).
  • TPU (Tensor Processing Unit): Google's custom AI ASIC built around huge 2D systolic arrays of multiply-accumulate (MAC) units.
  • FPGA (Field-Programmable Gate Array): Reconfigurable logic fabric programmed post-manufacture into custom hardware pipelines—great for ultra-low-latency deterministic streaming (telecommunications, sensor DSP, trading), though engineering requires hardware description languages and timing closure (ensuring every custom routed wire meets clock setup/hold rules).
  • ASIC (Application-Specific Integrated Circuit): Permanently etched silicon built for one workload—highest efficiency, highest upfront fabrication cost.

12.2 Matrix multiplication, systolic arrays and data reuse

Multiplying dense matrix A (M × K) by B (K × N) produces C (M × N) and requires approximately 2 × M × N × K floating-point operations (counting 1 multiply + 1 add = 2 FLOPs). Naively reading A and B from global memory for every output element hits the memory wall immediately.

Bucket-brigade analogy (Systolic Arrays): Instead of every worker walking back to the warehouse (HBM) for every single brick, a systolic array arranges hundreds of multiply-accumulate units in a 2D grid. Matrix weights stay stationary inside the cells while input activations rhythmically pulse from neighbour to neighbour—reusing every byte fetched from memory dozens of times!

Neural networks rarely require 64-bit scientific precision. Shrinking numbers from 32 bits to 16 or 8 bits cuts memory traffic in half (or quarters it) and multiplies Tensor Core throughput:

CHAPTER 13

SoC, chiplets, motherboard and thermal design

Architecture does not stop at logic gates. How dies are sliced, packaged, wired to a motherboard, powered by VRMs, and cooled directly governs sustained real-world speed.

13.1 System-on-Chip (SoC) integration

A System-on-Chip (SoC) integrates CPU cores, integrated GPU, NPU, memory controllers, media codecs, display engines, security enclaves, and high-speed I/O inside one tightly coupled silicon package. Keeping data on-package slashes wire capacitance and energy per bit—which is why smartphones and thin laptops rely heavily on SoCs.

13.2 Monolithic dies versus Chiplets

A monolithic chip etches every block onto a single large rectangle of silicon. As dies grow larger, tiny manufacturing dust defects ruin a much higher fraction of chips (lowering wafer yield and exploding cost). A chiplet architecture splits the processor into smaller specialised dies connected inside one package substrate or silicon interposer:

Modular apartment analogy: Building one giant 50-room mansion on a single slab means one foundation crack ruins the entire build. Building smaller prefabricated rooms (chiplets) lets you discard only a defective unit, use expensive marble only where needed (leading transistor nodes for compute), and connect them via covered walkways (interposers)—at the slight cost of walking between buildings.

13.3 Motherboard, VRM power delivery and Thermal Limits

A motherboard supplies the CPU socket, DIMM traces, PCIe lane routing, firmware flash chip, and chipset I/O. Crucially, power supplies output 12 V, while modern CPUs need ~0.8–1.4 V at 100+ amperes. Multi-phase Voltage Regulator Modules (VRMs) step down and smooth that power. Under load, processors dynamically scale voltage and frequency (DVFS) within strict electrical, power, and temperature limits.

Every watt of electrical power turns into heat. TDP (Thermal Design Power) is a cooling guideline for sustained baseline load—not the maximum instantaneous boost power a chip can draw. If heatsinks, thermal paste, or case airflow cannot shed that heat, the processor invokes thermal throttling, dropping clocks immediately to protect silicon.

Chapter 13 Summary: SoCs minimise energy per bit by integrating blocks tightly; chiplets improve yield and allow mixing process nodes at the cost of inter-die latency/packaging; and VRMs plus cooling headroom are integral parts of sustained compute performance.
CHAPTER 14

Performance: Amdahl's law, Roofline model and bottlenecks

Upgrading the fastest component in a system yields zero speedup if another stage is the bottleneck. Performance engineering is the science of locating and quantifying the true limiting resource.

14.1 Latency, throughput and the Iron Law of CPU Performance

Latency is the wall-clock time to complete one request (e.g., 50 ns DRAM read); throughput is the rate of completed requests per second (e.g., 50 GB/s). Increasing concurrency (pipelining, SIMD, multiple memory channels) boosts throughput without necessarily lowering single-item latency.

Iron Law:   CPU Time = Instruction Count (IC) × CPI × Cycle Time = (IC × CPI) / Frequency

Compilers influence IC and instruction mix; microarchitecture influences CPI; and silicon physics + power budget influence Frequency. Optimising one term can hurt another—for instance, raising clock speed via deeper pipelines often raises branch-misprediction CPI.

14.2 Amdahl's Law versus Gustafson's Law

Amdahl's Law answers: for a fixed workload size, if you accelerate fraction P by speedup factor S while the remaining serial fraction (1 − P) stays unchanged, what is the maximum total speedup?

Amdahl Speedup = 1 / [ (1 − P) + (P / S) ]   ⇒   As S → ∞, Max Speedup = 1 / (1 − P)

Even with an infinitely fast 10,000-core GPU, if 10% of your program remains serial on one CPU core, total speedup can never exceed 1 / 0.10 = 10×. In contrast, Gustafson's Law notes that when people get faster machines, they often scale problem size up to fill the same fixed wall-clock budget (e.g., training bigger AI models or rendering 4K instead of 720p), making parallel efficiency much higher than Amdahl's fixed-size limit suggests.

14.3 The Roofline Model (Compute-Bound vs. Memory-Bound)

The Roofline Model connects a hardware platform's two fundamental ceilings—Peak Compute (π, in GFLOP/s) and Peak Memory Bandwidth (β, in GB/s)—using a workload metric called Arithmetic (Operational) Intensity (AI):

Arithmetic Intensity (AI) = Total FLOPs / Total Bytes moved from Memory   [FLOPs/Byte]
Attainable Performance = min( Peak_Compute , Peak_Bandwidth × AI )
Ridge Point = Peak_Compute / Peak_Bandwidth   [FLOPs/Byte]
Assembly robot analogy: Imagine a welding robot capable of 100 welds per minute, fed by a conveyor belt delivering only 10 parts per minute. Buying a 500-weld/min robot changes output by zero—you are supply-line (memory) bound. First widen the conveyor belt (HBM/caching) or do more welds per part (higher arithmetic intensity).

14.4 Scientific benchmarking checklist

A benchmark number without methodology is noise. Always: (1) measure representative workloads, (2) run multiple trials and report median + tail latency (p95/p99), (3) separate cold-cache start from steady-state, (4) record ambient temperature, power cap, and clock frequency, and (5) verify whether the workload is bottlenecked by CPU, cache/DRAM, storage I/O, PCIe transfer, or thermal throttling.

Chapter 14 Summary: Latency and throughput are separate goals; Amdahl's law caps fixed-size speedup via the serial fraction 1 − P; and the Roofline Ridge Point tells you immediately whether to invest in memory bandwidth or compute units.

Boot, firmware, operating system and protection

At power-on, RAM is empty and the CPU knows nothing about files, windows, or users. A layered trust chain wakes the silicon, trains DRAM, loads the OS kernel, and locks applications inside hardware-enforced sandboxes.

15.1 Power-on boot chain and privilege rings

15.2 BIOS versus UEFI, Secure Boot and TPM

Legacy BIOS booted in 16-bit mode using 512-byte Master Boot Records (MBR). Modern systems use UEFI (Unified Extensible Firmware Interface), which runs in 64-bit mode, reads GPT partitions (supporting drives over 2 TB), trains DDR5 memory timings, and offers modular drivers. Secure Boot checks cryptographic signatures along the boot chain before executing bootloaders, while a TPM (Trusted Platform Module) securely stores encryption keys and records cryptographic hashes (measurements) of boot stages so disk encryption (like BitLocker/LUKS) detects tampering.

15.3 Processes, threads, context switches and system calls

A process is an isolated execution container with its own virtual address space (Section 7.4) and open file descriptors. A thread is an execution path inside a process—sharing memory with sibling threads while keeping its own PC, stack, and registers. Switching the CPU between threads (a context switch) saves/restores registers and—when switching processes—changes the page-table base register, incurring indirect overhead from cold caches and TLB misses.

Bank-teller glass analogy: User Mode is the public lobby; Kernel Mode is behind bulletproof glass with the vault keys. An application cannot simply walk behind the counter to read your SSD—it slides a formal request slip (a system call) under the glass, and the OS kernel checks permissions before fulfilling it.
Chapter 15 Summary: UEFI trains hardware and hands control to the OS kernel; privilege levels prevent applications from corrupting hardware or sibling processes; system calls mediate safe transitions; and Secure Boot + TPM anchor early boot trust.
CHAPTER 16

Reliability, Hamming codes and ECC

Cosmic rays, alpha particles, and voltage noise occasionally flip bits inside dense DRAM cells or high-speed interconnects. Error-correcting codes add minimal mathematical redundancy so hardware can catch and silently repair flipped bits before data silently corrupts.

16.1 Parity and Hamming Distance

Adding one even parity bit ensures the total count of 1s in a codeword is even (e.g., data 1011001 has four 1s ⇒ even parity bit = 0). A single parity bit detects any odd number of bit flips, misses any even number of flips, and cannot tell which bit flipped.

The Hamming distance between two codewords is the number of bit positions where they differ. If a coding scheme guarantees minimum distance d between every pair of valid codewords:

Detect up to (d − 1) bit errors   |   Correct up to ⌊(d − 1) / 2⌋ bit errors

16.2 Hamming Codes and SECDED

A Hamming code places parity bits at power-of-two positions (1, 2, 4, 8, ...). Each parity bit protects a specific binary pattern of bit positions. To protect m data bits using r Hamming parity bits, the code must satisfy:

2^r ≥ m + r + 1

For m = 64 data bits (one standard DDR word), r = 7 works because 2⁷ = 128 ≥ 64 + 7 + 1 = 72. Adding 1 extra overall parity bit increases the minimum Hamming distance from 3 to 4, creating SECDED (Single Error Correction, Double Error Detection)—requiring 64 + 8 = 72 bits total (which is why ECC DIMMs are 72 bits wide instead of 64 bits).

Crossword checksum analogy: Imagine arranging digits in a grid with row sums and column sums. If a single number gets smudged, exactly one row sum and one column sum turn out wrong—their intersection points straight to the exact damaged square so you can restore it! In Hamming codes, the failing parity checks form a binary address called the syndrome that points directly to the flipped bit position.
Worked GATE Example — Hamming(7,4) Syndrome Error Location: Encode 4-bit data 1011 using even-parity Hamming(7,4), then suppose bit position 6 flips in transit. Show how the receiver locates and fixes it.
Step 1 (Place data in non-power-of-2 slots 3,5,6,7): p1, p2, d3=1, p4, d5=0, d6=1, d7=1.
Step 2 (Compute even parity bits):
• p1 checks positions 1,3,5,7 (LSB=1): d3⊕d5⊕d7 = 1⊕0⊕1 = 0.
• p2 checks positions 2,3,6,7 (bit2=1): d3⊕d6⊕d7 = 1⊕1⊕1 = 1.
• p4 checks positions 4,5,6,7 (bit4=1): d5⊕d6⊕d7 = 0⊕1⊕1 = 0.
Transmitted codeword (pos 1..7): 0 1 1 0 0 1 1.
Step 3 (Bit 6 flips → Received): 0 1 1 0 0 0 1.
Step 4 (Compute Syndrome s4 s2 s1):
• s1 (1,3,5,7) = 0⊕1⊕0⊕1 = 0 (OK)
• s2 (2,3,6,7) = 1⊕1⊕0⊕1 = 1 (FAIL)
• s4 (4,5,6,7) = 0⊕0⊕0⊕1 = 1 (FAIL)
Syndrome = s4 s2 s1 = 110₂ = 6! The hardware immediately flips bit 6 back from 0 → 1, restoring 1011 cleanly.

16.3 Reliability is always layered

No single mechanism makes a computer infallible: ECC RAM protects DRAM words; SSD controllers apply powerful LDPC error correction over noisy NAND flash; PCIe 6.0+ adds CRC + FEC per FLIT; filesystems like ZFS/Btrfs add end-to-end block checksums; and RAID or cloud replication protects against whole-drive failures. Even with all of those, hardware ECC cannot undo a software bug that intentionally overwrites a valid file.

Chapter 16 Summary: Parity detects 1 error; Hamming distance sets correction power; Hamming syndromes pinpoint single-bit flips in binary; SECDED adds 8 check bits per 64-bit word (72-bit ECC DIMMs); and real reliability requires layered defence.

Show solution

Q6. Why does a 99% L1 cache hit rate not automatically prove fast memory performance? Concept

Show solution

If the remaining 1% misses all the way to DRAM at 200 cycles, 0.01 × 200 = 2.0 cycles added to every memory access—tripling effective memory latency! Both hit time and miss penalty matter, alongside TLB misses and memory bandwidth.

Q7. Distinguish DDR5, GDDR, and HBM in one crisp paragraph. Concept

Show solution

DDR5 is mainstream CPU system DRAM optimised for capacity and dual-32-bit subchannels per DIMM. GDDR (GDDR6/7) is graphics DRAM using high-speed per-pin signalling around discrete GPUs. HBM vertically stacks DRAM dies on a silicon interposer with ultra-wide (1,024-bit+) interfaces for maximum bandwidth per watt in AI/HPC accelerators.

Q8. Explain cache coherence versus memory consistency. Concept

Show solution

Coherence governs visibility of writes to a single memory location across cached copies (e.g., MESI invalidates stale copies). Consistency defines the legal ordering of reads and writes across multiple different memory locations visible to concurrent threads.

Q9. How does an out-of-order CPU execute instructions out of order without breaking program correctness or exceptions? Concept

Show solution

Register renaming removes false WAR/WAW dependencies, and the Reorder Buffer (ROB) tracks all in-flight µops in original program order—retiring results to architectural state strictly in order and flushing younger speculative work on exceptions or branch mispredictions.

Q10. Does a 64-bit CPU necessarily have 64 physical address wires? Concept

Show solution

No. “64-bit” describes the ISA's register and virtual pointer width. Real CPUs typically implement 48 or 57 virtual address bits (enforcing canonical addresses) and 40–52 physical address bits to avoid wasting silicon on unreachable exabytes of RAM.

Q11. Give three concrete reasons real DRAM throughput is lower than the theoretical channel calculation. Concept

Show solution

Periodic refresh cycles (tRFC), row-buffer conflicts requiring precharge + activate (tRP + tRCD), read-to-write bus turnaround delays, non-sequential access patterns, and contention across cores/DMA engines.

Q12. Why can a CPU use separate L1i and L1d caches while still presenting a unified address space to software? Concept

Show solution

This is a modified Harvard microarchitecture: both L1 caches back onto a unified L2/L3/DRAM address space, letting the pipeline fetch instructions and load data on the exact same cycle without structural hazards.

1. 0 (Set 0) → MISS → Set 0: [0]
2. 2 (Set 0) → MISS → Set 0: [0, 2]
3. 1 (Set 1) → MISS → Set 1: [1]

5. 4 (Set 0) → MISS (evicts LRU = 2) → Set 0: [0, 4]

7. 1 (Set 1) → HIT → Set 1: [1]
8. 4 (Set 0) → HIT → Set 0: [2, 4]

Glossary of essential terms

ALU
Arithmetic Logic Unit; executes integer math, bitwise logic, shifts, and comparisons.
AMAT / EMAT
Average / Effective Memory Access Time combining hit latency, miss rates, and miss penalties.
Amdahl's Law
Fixed-workload speedup ceiling set by the unaccelerated serial fraction 1 − P.
ASIC
Application-Specific Integrated Circuit; custom permanently etched silicon for one target domain.
Bandwidth
Maximum data volume transferred per unit time (e.g., GB/s).
BF16 (bfloat16)
16-bit AI float (1 sign, 8 exponent, 7 mantissa) retaining FP32's dynamic range.
Branch Predictor
Hardware guessing branch direction and target address so the pipeline stays full.
Cache Coherence
Ensures all CPU cores observe a consistent value for any single memory address (e.g., MESI).
Cache Line
Fixed-size contiguous block (commonly 64 B) moved between cache levels and DRAM.
Canonical Address
64-bit virtual address whose unused upper bits sign-extend the highest implemented virtual bit.
Chiplet
Smaller specialised silicon die (e.g., compute CCD or I/O die) joined inside one package.
Clock Skew / Jitter
Skew: spatial difference in clock arrival across a chip; Jitter: random cycle-to-cycle edge drift.
CPI / IPC
Cycles Per Instruction / Instructions Per Cycle; workload-dependent execution efficiency metrics.
Cycle Stealing
DMA mode borrowing individual memory bus cycles one word at a time between CPU accesses.
DDR / MT/s
Double Data Rate (transfers on both clock edges), measured in Million Transfers per second.
DMA
Direct Memory Access; hardware engine copying blocks between I/O and RAM without CPU word loops.
DRAM
Dynamic RAM (1T1C capacitor cell); high-density volatile main memory needing periodic refresh.
ECC / SECDED
Error-Correcting Code; SECDED corrects 1-bit errors and detects 2-bit errors per protected word.
Endianness
Byte ordering in memory (little-endian stores LSB at lowest address; big-endian stores MSB first).
FLIT
Flow Control Unit; fixed-size 256-byte packet unit used in PCIe 6.0 and 7.0 with FEC.
FLOPS / TOPS
Floating-point operations/s and Tera Operations/s; meaningful only with precision & sparsity stated.
Forwarding (Bypassing)
Routing a freshly computed ALU/MEM result directly into the next instruction's EX inputs to avoid stalls.
FPGA
Field-Programmable Gate Array; post-manufacture reconfigurable hardware logic fabric.
FTL
Flash Translation Layer; SSD controller firmware mapping logical blocks to physical NAND pages.
GDDR / HBM
High-bandwidth GPU/accelerator DRAM families; HBM stacks dies vertically on an interposer.
Hazard (RAW/WAR/WAW)
Pipeline conflict preventing the next instruction from advancing on schedule.
IOMMU
I/O Memory Management Unit translating and isolating physical memory addresses for DMA devices.
ISA
Instruction Set Architecture; the software-visible contract (e.g., x86-64, Arm AArch64, RISC-V).
Latch / Flip-Flop
1-bit sequential storage elements; latches are level-sensitive, flip-flops are clock-edge-triggered.
Memory Coalescing
GPU hardware combining adjacent threads' VRAM loads into fewer wide memory transactions.
Memory Consistency
Architectural rules defining the legal ordering of memory accesses across different addresses.
Microarchitecture
Internal silicon implementation of an ISA (pipelines, caches, OoO queues, execution ports).
MMIO
Memory-Mapped I/O; mapping peripheral control/status registers into the normal memory address space.
MMU / TLB
Memory Management Unit (translates virtual→physical addresses) and its fast Translation Lookaside Buffer.
NVMe
Non-Volatile Memory Express; high-parallelism queue-based storage protocol commonly over PCIe.
OoO / ROB
Out-of-Order execution guided by a Reorder Buffer that commits finished µops strictly in program order.
Page Fault
MMU exception raised when a virtual page is unmapped, paged out to disk, or violates access permissions.
PAM4
4-level Pulse Amplitude Modulation carrying 2 bits per symbol (used in PCIe 6.0/7.0 and GDDR6X/7).
PCIe
Peripheral Component Interconnect Express; packet-based, full-duplex serial I/O interconnect.
Propagation Delay
Physical time for a logic gate's output voltage to settle after an input switches.
RDMA
Remote Direct Memory Access; direct memory transfers between networked hosts bypassing CPU copies.
Roofline Model
Performance model bounding a kernel by the minimum of Peak Compute and (Peak Bandwidth × Arithmetic Intensity).
Setup / Hold Time
Minimum time data must stay stable before (setup) and after (hold) a flip-flop's clock edge.
SIMD / SIMT
Single Instruction Multiple Data (CPU vector lanes) vs. Single Instruction Multiple Threads (GPU warps).
SMT
Simultaneous Multithreading; running multiple hardware thread contexts on one shared physical core.
SoC
System-on-Chip integrating CPU, GPU, NPU, memory controller, and I/O in one tight package.
SRAM
Static RAM (6T bistable latch); ultra-fast cache memory requiring no refresh while powered.
Syndrome
Binary vector of parity-check failures in a Hamming code that points straight to a flipped bit position.
Timing Closure
Chip/FPGA verification proving every routed signal path meets setup and hold constraints at target frequency.
TLP
Transaction Layer Packet; the formatted PCIe packet carrying memory/I/O commands and payload data.
UEFI / TPM
Modern 64-bit platform boot firmware (UEFI) and hardware security chip (TPM) anchoring Secure Boot & keys.
Warp Divergence
Throughput drop when threads inside a GPU warp take different branch paths and execute serially under masks.
Wear Levelling & Write Amp
FTL spreading erases across NAND blocks evenly; extra internal flash writes caused by block-level garbage collection.
